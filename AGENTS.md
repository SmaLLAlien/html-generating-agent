# Инструкции для кодовых агентов

Монорепозиторий без workspace-тулинга: два независимых npm-пакета рядом.
`npm install` делается в каждом отдельно.

## Сборка и проверка

```bash
cd ai-widgets && npm run build
```

```bash
cd my-express-server && node node_modules/typescript/lib/tsc.js --noEmit
```

**`npm run build` в `my-express-server` падает — это ожидаемо.** Установлен TypeScript 7.0.2,
у которого `bin/tsc` без расширения, а пакет объявлен `"type": "module"`; Node 20 такой файл
не грузит и валится с `ERR_UNKNOWN_FILE_EXTENSION`. `npx tsc` и `node_modules/.bin/tsc.cmd`
падают так же. Рабочий путь — вызвать `lib/tsc.js` напрямую, как выше. Чинится либо откатом
на TypeScript 5.x, либо правкой скрипта `build` в `package.json`.

Запуск для ручной проверки — два терминала, `npm run dev` на сервере и `npm start` в клиенте.
Сервер под `tsx watch`: правки в `src/` подхватываются сами, изменения в `.env` — нет,
нужен перезапуск.

## Тесты

Автотестов в репозитории нет. Проверка делается скриптами на `tsx`, которые импортируют
модули сервера напрямую и гоняют `runAgent` без HTTP:

```bash
cd my-express-server && npx tsx /путь/к/скрипту.mts
```

Из-за ESM с абсолютными путями импорт из файла вне проекта пишется как
`import { runAgent } from 'file:///D:/.../my-express-server/src/agent.ts'`, а `dotenv`
подключается так же по абсолютному URL — иначе Node не разрешит bare-спецификатор.

Что стоит прогонять после правок ядра: юнит-тесты `evictOldWidgets` и `validateWidget`
(чистые функции, быстро), проверку API-обвязки по HTTP, живой прогон 5–6 ходов с замером
`contextTokens`.

**Пороги контекста проверяются малым бюджетом, а не длинным диалогом:**

```powershell
cd my-express-server; $env:CONTEXT_BUDGET_TOKENS='2500'; npm run dev
```

Тогда 80% и 100% достигаются за три-четыре хода. Синтаксис PowerShell намеренно: bash-форма
`VAR=x npm run dev` здесь не работает (см. «грабли окружения» ниже). Переменная из оболочки
побеждает — `dotenv` не перетирает уже заданные значения `process.env`.

## Что где лежит

| Файл | Ответственность |
|---|---|
| `src/agent.ts` | Ядро: `streamText`, цикл шагов, системный промпт, эфемерный блок состояния, учёт токенов |
| `src/tools.ts` | Три инструмента агента, `validateWidget`, `stripJavaScript` |
| `src/memory.ts` | `evictOldWidgets` — вытеснение кода виджетов из истории |
| `src/sessions.ts` | `Map` сессий, реестр вариантов, TTL |
| `src/models.ts` | Реестр моделей, резолв провайдера, настройки вызова по поколениям (`callSettingsFor`) |
| `src/brand.ts` | Фирменный стиль, вставляется в системный промпт |
| `src/config.ts` | Бюджет контекста и лимит шагов. Единого места для env-переменных нет: `GEMINI_MODEL` и ключ читает `models.ts`, `PORT` — `index.ts` |
| `src/events.ts` | Union событий SSE — **зеркалится** в `ai-widgets/src/app/chat/chat.models.ts` |
| `src/chat.router.ts` | HTTP-эндпоинты, SSE, страж бюджета |

Клиентская часть целиком в `ai-widgets/src/app/chat/`.

## Конвенции

- **Комментарии и строки — на русском.** Весь UI, системный промпт и сообщения об ошибках
  тоже. Исключение: `index.ts` исторически на украинском — и логи старта, и тело ответа
  `GET /` («TypeScript Express сервер працює!»).
- **ESM.** В относительных импортах на сервере обязательно расширение `.js`, даже для
  `.ts`-файлов: `import { runAgent } from './agent.js'`.
- **Клиент на сигналах.** `HttpClient` не используется — голый `fetch` в `chat.service.ts`
  с ручным разбором SSE. Не тащите RxJS без нужды.
- **Контракт SSE дублируется** в `events.ts` и `chat.models.ts`. Меняя одно, меняйте второе —
  типы не связаны, компилятор рассинхрон не поймает.
- **Комментарий объясняет «почему», а не «что».** В коде есть несколько мест с
  неочевидными решениями (порядок полей, выбор `usage` вместо `totalUsage`,
  переписывание истории на месте) — там комментарии обязательны.

## Чего не делать

- **Не читать и не печатать `my-express-server/.env`.** Ключ не нужен для работы с кодом.
  Проверить, что он подхватился, можно косвенно: при старте нет предупреждения
  `⚠️ GEMINI_API_KEY не задан`. В логах ключа нет — Gemini получает его заголовком
  `x-goog-api-key`, а `APICallError` из AI SDK заголовки запроса не хранит.
- **Не коммитить сборки.** `ai-widgets/dist` закрыт паттерном `/dist` в
  `ai-widgets/.gitignore`, `my-express-server/dist` — отдельной строкой в корневом
  `.gitignore` (корневой `/dist` заякорен на корень и вложенные папки не покрывает).
- **Не добавлять инструменты агенту без нужды.** Их три, и `gemini-2.5-flash` тем надёжнее,
  чем меньше выбор. Каждый новый — риск, что модель начнёт звать не то.
- **Не класть изменчивые данные в системный промпт.** Дата, номер хода, заполненность
  контекста, каталог вариантов идут эфемерным сообщением в хвост запроса. В системном
  промпте они убивали бы префиксный кеш Gemini на каждом ходу.
- **Не пересобирать историю вручную.** В `session.messages` кладётся `result.response.messages`
  дословно. У Gemini 3 в `providerOptions` каждой части лежат подписи мыслей, и их нужно
  вернуть модели без изменений. Если сохранять только текст, подписи умрут — **молча**:
  провайдер подставит `SKIP_THOUGHT_SIGNATURE_VALIDATOR`, запрос пройдёт, а преемственность
  рассуждений сломается. Меняя работу с историей, прогоняйте тест сохранности подписей.
- **Не путать `usage` и `totalUsage`.** Размер контекста — из `usage` (последний шаг),
  расход на размышления — из `totalUsage` (все шаги). Перепутать легко, ошибка в обе
  стороны молчаливая. Обоснование в `docs/agent-architecture.md`.
- **Не раздувать системный промпт «на всякий случай».** Каждый токен там платится в каждом
  запросе. Критерий включения: изменится ли поведение агента. Если проверить не удалось —
  не добавлять.

## Известные грабли окружения

- `git` недоступен в Bash-инструменте — работает только через PowerShell.
- Git ругается `LF will be replaced by CRLF` из-за `core.autocrlf=true`. Это не ошибка;
  в репозитории остаются LF.
- Angular-сборка следит за бюджетом стилей: `anyComponentStyle` в `angular.json`
  поднимался уже дважды, сейчас 12kB/20kB. Бюджет считается по **собранному и
  минифицированному** стилю, а не по размеру файла на диске — сравнивать порог с
  исходником бессмысленно, проверять только сборкой. `chat.component.css` держится
  около 8.4 КБ собранного, так что следующая крупная правка стилей снова упрётся.
