# Помощник по виджетам

Чат-ассистент, который собирает HTML-виджеты без JavaScript. Сотрудник описывает,
что нужно; агент показывает вариант, правит его по замечаниям и завершает диалог,
когда вариант одобрен. Каждая версия получает номер, к ней можно вернуться.

- **`ai-widgets/`** — Angular 19, плавающий чат-виджет. Только сигналы, без RxJS-стора.
- **`my-express-server/`** — Express 5 + TypeScript, агент на Vercel AI SDK v7
  (`ai@7`, `@ai-sdk/google@4`) и Google Gemini.
- **`docs/agent-architecture.md`** — как устроен агент внутри: инструменты, промпт, контекст.
- **`AGENTS.md`** — рабочие инструкции для кодовых агентов (сборка, проверка, грабли).

## Быстрый старт

Нужен Node 22+ (требование `ai@7`) и ключ Google Gemini.

```bash
cp "my-express-server/.env.example" "my-express-server/.env"
```

Впишите `GEMINI_API_KEY=...` в созданный файл. Дальше два терминала:

```bash
cd my-express-server && npm install && npm run dev
```

```bash
cd ai-widgets && npm install && npm start
```

Клиент поднимется на `http://localhost:4200`, дев-прокси перенаправит `/api` на
`http://localhost:3000` (см. `ai-widgets/proxy.conf.json`).

## Переменные окружения

Все читаются на старте сервера из `my-express-server/.env`. Файл в `.gitignore`.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `GEMINI_API_KEY` | — | **Обязательна.** Ключ Google Gemini |
| `GOOGLE_GENERATIVE_AI_API_KEY` | — | Запасное имя для того же ключа |
| `GEMINI_MODEL` | `gemini-2.5-flash` | Модель по умолчанию. Игнорируется, если id нет в реестре `src/models.ts` |
| `CONTEXT_BUDGET_TOKENS` | `300000` | Рабочий бюджет контекста. На 80% предупреждение, на 100% диалог блокируется |
| `MAX_AGENT_STEPS` | `6` | Максимум шагов агентного цикла за один ход пользователя |
| `MAX_OUTPUT_TOKENS` | `32000` | Потолок выходных токенов на шаг |
| `MAX_SESSIONS` | `500` | Потолок сессий в памяти; при переполнении вытесняется самая давняя |
| `MAX_VARIANTS_PER_SESSION` | `50` | Потолок вариантов в одном диалоге |
| `MAX_MESSAGE_LENGTH` | `8000` | Длина сообщения пользователя, символов (лишнее обрезается) |
| `MAX_ATTACHMENT_BYTES` | `4194304` | Потолок одной картинки после ужатия на клиенте |
| `MAX_ATTACHMENTS_PER_MESSAGE` | `4` | Сколько картинок можно приложить к одному сообщению |
| `MAX_ATTACHMENTS_PER_SESSION` | `20` | Потолок картинок на диалог |
| `ATTACHMENT_BODY_LIMIT` | `8mb` | Лимит тела для маршрута загрузки; на остальных остаётся 1 МБ |
| `PORT` | `3000` | Порт сервера. При смене поправьте `ai-widgets/proxy.conf.json` |

Менять значения на лету нельзя — `dotenv` читает файл только при запуске, а `tsx watch`
следит за `src/`, но не за `.env`. После правки перезапустите сервер.

## HTTP API

Всё под префиксом `/api/chat`.

### `GET /models`

Список моделей и настройки бюджета — клиент запрашивает его при старте.

```json
{
  "models": [{ "id": "gemini-2.5-pro", "label": "Gemini 2.5 Pro",
               "contextWindow": 1048576, "hint": "Точнее и надёжнее с инструментами, но медленнее" }],
  "defaultModelId": "gemini-2.5-flash",
  "contextBudget": 300000,
  "warnRatio": 0.8
}
```

Выше показана одна модель для краткости. Реальный состав реестра:

| Модель | Поколение | Мышление | Когда брать |
|---|---|---|---|
| `gemini-2.5-flash` | 2.5 | — | По умолчанию: проверено на этом проекте |
| `gemini-2.5-pro` | 2.5 | — | Когда нужна точность, а скорость не важна |
| `gemini-3.6-flash` | 3 | `low` | Новое поколение, лучше следует инструментам |
| `gemini-3.5-flash-lite` | 3 | `minimal` | Быстро и дёшево, почти без размышлений |
| `gemini-3.1-pro-preview` | 3 | `medium` | Самая сильная и самая дорогая |

Модель переключается в середине диалога без потери истории и вариантов. Подробности
про поколения и размышления — в [docs/agent-architecture.md](docs/agent-architecture.md).

### `POST /session`

Запрос: `{ "ldap": "i.ivanov", "fullName": "Иванов Иван Иванович" }` — оба поля обязательны.
Ответ `201`: `{ "sessionId": "uuid", "modelId": "gemini-2.5-flash" }`.
Ошибка `400`: `{ "error": "Поля ldap и fullName обязательны" }`.

### `PATCH /:sessionId/model`

Запрос: `{ "modelId": "gemini-2.5-pro" }`. Ответ `200`: `{ "modelId": "gemini-2.5-pro" }`.
История и варианты сессии сохраняются. Ошибки: `404` — сессии нет, `400` — модель неизвестна.

### `POST /:sessionId/attachment`

Загрузка картинки. Отдельный маршрут: у него увеличенный лимит тела, остальные
остаются на строгом 1 МБ.

Запрос: `{ "name": "shot.png", "mediaType": "image/png", "dataBase64": "..." }`.
Принимаются только PNG, JPEG и WebP; сигнатура файла сверяется с заявленным типом.
Ответ `201`: `{ "id": "att_1_a3f9c2", "name", "sizeBytes", "approxTokens" }`.

### `POST /:sessionId/message`

Тело — одна из форм:

| Форма | Смысл |
|---|---|
| `{ "text": "..." }` | Обычное сообщение |
| `{ "text": "...", "attachmentIds": ["att_1_a3f9c2"] }` | Сообщение с картинками; `text` можно опустить |
| `{ "action": "accept", "variant": 3 }` | Нажата «Принять» под вариантом #3 |
| `{ "action": "revisit", "variant": 1, "text": "..." }` | Взять вариант #1 за основу; `text` — необязательный комментарий |

Ответ — поток SSE (`text/event-stream`). Кадры вида `data: <json>\n\n`, без поля `event:`:
тип различается по ключу `type`.

Ошибки до открытия потока — обычный JSON: `404` (сессии нет), `400` (нет варианта либо
не передано ни `text`, ни `action`).

### `DELETE /:sessionId`

Удаляет сессию вместе с историей и всеми вариантами. Ответ `204`, идемпотентен.

## События SSE

| `type` | Поля | Когда |
|---|---|---|
| `text` | `delta` | Приращение текста. **Не** накопленный текст — клиент склеивает сам |
| `widget` | `variant`, `title`, `basedOn`, `html` | Агент выдал новую версию виджета |
| `status` | `stage`, `variant?` | `widget-start` — начал собирать виджет; `fetching-variant` — тянет старый вариант; `fetching-attachment` — смотрит картинку заново |
| `usage` | `contextTokens`, `budget`, `percent`, `cachedTokens?`, `reasoningTokens?` | Один раз в конце хода |
| `limit` | `contextTokens`, `budget` | Бюджет исчерпан, модель не вызывалась |
| `done` | `finished`, `truncated?` | Ход завершён; `finished: true` — агент закрыл диалог; `truncated: true` — ответ обрезан по лимиту длины |
| `error` | `error`, `code`, `retryable` | Ошибка. `code`: `rate-limit` / `safety` / `auth` / `model` / `network` / `tool` / `unknown`. Внутренние детали наружу не отдаются |

Ошибки до открытия потока приходят обычным JSON: `404` — сессии нет, `400` — неверное
тело, `409` — в этой сессии уже идёт ответ, `413` — тело больше 1 МБ.

## Известные ограничения

**Нет персистентности.** Сессии живут в `Map` в памяти процесса ([sessions.ts](my-express-server/src/sessions.ts)).
Отсюда три следствия:

- перезапуск сервера стирает все диалоги, варианты и отметки «принято»;
- нельзя поднять больше одного инстанса — за балансировщиком запрос уйдёт в процесс,
  где этой сессии нет, и получит `404`;
- диалог нельзя продолжить после перезагрузки вкладки: `sessionId` живёт в переменной
  компонента, а не в `localStorage`. Обработчик `beforeunload` при уходе со страницы
  ещё и удаляет сессию на сервере (`DELETE` с `keepalive`), чтобы она не висела до TTL.

Сессия удаляется сразу по `DELETE` или после **часа** молчания; уборщик ходит раз в 5 минут.

**Нет аутентификации.** `ldap` и ФИО пользователь вводит сам, сервер их не проверяет.
Изоляция держится на неугадываемости `sessionId` (`randomUUID`), а не на подтверждённой
личности: два пользователя не видят варианты друг друга, но выдать себя за коллегу можно.
При переносе в среду с настоящим LDAP/SSO сессию нужно привязывать к проверенному логину.

**Контекст не сжимается.** При достижении бюджета диалог блокируется с предложением начать
новый — автосуммаризация сознательно не делается, причины в
[docs/agent-architecture.md](docs/agent-architecture.md).

**`npm run build` в `my-express-server` не работает** — баг окружения, не проекта. Обходной
путь описан в [AGENTS.md](AGENTS.md). Разработке не мешает: `npm run dev` работает нормально.
